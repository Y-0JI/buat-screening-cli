# Roadmap: Universal Symbol Discovery

## Overview

**Epic:** Universal Symbol Discovery

**Goal**

Build a reliable, extensible, and provider-agnostic symbol discovery
system that always supplies a valid stock universe for the screening
engine regardless of the underlying data source.

------------------------------------------------------------------------

# Phase 1 --- Stabilize Data Providers (Highest Priority)

## Objective

Ensure the application can always retrieve stock symbols from multiple
providers.

### Scope

-   Support multiple data providers.
-   Implement automatic fallback when a provider fails.
-   Cache the latest successful symbol list.
-   Continue operating when external services are temporarily
    unavailable.
-   Improve reliability and resiliency.

### Expected Outcome

The screening engine always receives a symbol list even if one provider
is unavailable.

------------------------------------------------------------------------

# Phase 2 --- Symbol Validation

## Objective

Ensure every discovered symbol is valid before entering the screening
pipeline.

### Scope

-   Validate symbol format.
-   Reject invalid or malformed entries.
-   Prevent empty or corrupted symbol lists from propagating.

### Expected Outcome

Only verified symbols are passed into downstream components.

------------------------------------------------------------------------

# Phase 3 --- Symbol Normalization

## Objective

Standardize symbol formatting across all providers.

### Scope

-   Convert provider-specific formats into a single internal
    representation.
-   Ensure consistent symbol handling throughout the application.
-   Reduce provider-specific logic outside the discovery layer.

### Expected Outcome

Every component works with a single canonical symbol format.

------------------------------------------------------------------------

# Phase 4 --- Symbol Deduplication

## Objective

Merge results from multiple providers into one clean symbol universe.

### Scope

-   Remove duplicate symbols.
-   Preserve unique entries only.
-   Produce a consistent final universe.

### Expected Outcome

The application maintains a clean, duplicate-free list of symbols.

------------------------------------------------------------------------

# Phase 5 --- Provider Health & Monitoring

## Objective

Improve visibility into provider reliability and simplify
troubleshooting.

### Scope

-   Record provider status.
-   Produce meaningful logs.
-   Surface clear user-friendly error messages.
-   Make failures easier to diagnose.

### Expected Outcome

Provider issues become easy to identify and debug.

------------------------------------------------------------------------

# Phase 6 --- Extensible Provider Architecture

## Objective

Design the discovery layer so additional providers can be added without
modifying the screening engine.

### Scope

-   Keep provider implementations modular.
-   Isolate provider-specific logic.
-   Enable future integrations with minimal changes.

### Expected Outcome

The system can grow by adding new providers without affecting existing
business logic.

------------------------------------------------------------------------

# Final Architecture Goals

When all phases are complete, Universal Symbol Discovery should provide:

-   A single entry point for symbol discovery.
-   Multiple provider support.
-   Automatic fallback.
-   Symbol validation.
-   Symbol normalization.
-   Duplicate removal.
-   Provider monitoring.
-   Modular and extensible architecture.
-   Reliable symbol delivery for every screening workflow.

------------------------------------------------------------------------

# Recommended Implementation Order

1.  Stabilize Data Providers
2.  Symbol Validation
3.  Symbol Normalization
4.  Symbol Deduplication
5.  Provider Health & Monitoring
6.  Extensible Provider Architecture

This roadmap intentionally focuses on high-level objectives and expected
outcomes rather than implementation details, making it suitable for AI
coding agents while leaving flexibility for architectural decisions.
