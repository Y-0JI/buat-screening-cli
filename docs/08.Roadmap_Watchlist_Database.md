# Roadmap: Watchlist Database

## Overview

**Epic:** Watchlist Database

### Goal

Build a centralized, scalable, and provider-independent watchlist system
that enables users to organize, track, and manage securities while
serving as the foundation for AI analysis, alerts, portfolio monitoring,
and future web features.

------------------------------------------------------------------------

# Phase 1 --- Core Watchlist Management (Highest Priority)

## Objective

Provide a reliable way to create and manage watchlists.

### Scope

-   Create multiple watchlists.
-   Rename watchlists.
-   Delete watchlists.
-   Add symbols.
-   Remove symbols.
-   Reorder symbols.
-   Prevent duplicate entries.

### Expected Outcome

Users can organize securities into structured watchlists.

------------------------------------------------------------------------

# Phase 2 --- Watchlist Metadata

## Objective

Store additional information about each watchlist.

### Scope

-   Watchlist name
-   Description
-   Creation date
-   Last modified date
-   Tags
-   Notes
-   Favorite status

### Expected Outcome

Watchlists become easier to organize and search.

------------------------------------------------------------------------

# Phase 3 --- Symbol Metadata

## Objective

Maintain useful information for every saved symbol.

### Scope

-   Company name
-   Exchange
-   Sector
-   Industry
-   Market
-   Currency
-   **Catatan:** Field "Provider identifier" tidak didukung saat ini karena abstraction layer provider belum mengekspos provider mana yang berhasil memberi data.

### Expected Outcome

The watchlist contains rich contextual information beyond ticker
symbols.

------------------------------------------------------------------------

# Phase 4 --- Data Synchronization

## Objective

Keep watchlist data accurate as provider data changes.

### Scope

-   Refresh company metadata
-   Handle renamed symbols
-   Handle delisted securities
-   Detect unavailable providers
-   Maintain data consistency

### Expected Outcome

Watchlists remain accurate over time.

------------------------------------------------------------------------

# Phase 5 --- Search & Filtering

## Objective

Enable fast discovery of symbols and watchlists.

### Scope

-   Search by ticker
-   Search by company
-   Filter by sector
-   Filter by market
-   Filter by tags
-   Sort by different criteria

### Expected Outcome

Users can quickly locate relevant securities.

------------------------------------------------------------------------

# Phase 6 --- Extensible Storage Architecture

## Objective

Allow different storage backends without changing application logic.

### Scope

-   Local storage
-   SQLite
-   PostgreSQL
-   Cloud database
-   Future synchronization support

### Expected Outcome

The storage layer can evolve independently of business logic.

------------------------------------------------------------------------

# Final Architecture Goals

-   Centralized watchlist management
-   Rich metadata
-   Provider-independent storage
-   Fast search and filtering
-   Reliable synchronization
-   Modular storage architecture
-   Foundation for AI and web applications

------------------------------------------------------------------------

# Future Integrations

-   AI Research
-   Screening History
-   Price Alerts
-   News Monitoring
-   AI Watchlist Summaries
-   Risk Monitoring
-   Dashboard Widgets
-   Mobile Applications
-   Multi-device Synchronization

------------------------------------------------------------------------

# Recommended Implementation Order

1.  Core Watchlist Management
2.  Watchlist Metadata
3.  Symbol Metadata
4.  Data Synchronization
5.  Search & Filtering
6.  Extensible Storage Architecture

------------------------------------------------------------------------

# Success Criteria

-   Users can manage multiple watchlists efficiently.
-   Watchlists remain synchronized with provider data.
-   Symbols include rich metadata.
-   Storage is provider-independent.
-   Architecture is modular and extensible.
-   Ready for AI, portfolio, and web features.

------------------------------------------------------------------------

## Alignment with Product Vision

This roadmap is intentionally high-level and implementation-agnostic. It
defines product objectives and expected outcomes rather than prescribing
technical implementation details, making it suitable for AI coding
agents while remaining aligned with the long-term vision of an
AI-powered equity research platform.
